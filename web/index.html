How to use this demo

This is a control panel for safely replacing one AI model with another while it is serving real people. The old model is v1. The new one is v2 — the same model compressed to run faster. The question this whole system exists to answer is: can we trust v2 enough to let it start answering real requests? You are the person deciding.

Step 1 · Predict tab

Send a sentence

Press Surprise me for a random sentence, or type your own, then press Classify. A large POSITIVE or NEGATIVE appears below the box — that is the answer, and the small print under it says which model produced it.

Step 2 · Comparison tab

See if they agree

Look at the first number, Average gap. That is how far apart the two models were — near 0 means they agree. Then look at the chart below it: every dot is one sentence, and a pink dot is one where they gave opposite answers.

Step 3 · Rollout tab

Give the new model traffic

Press Promote. Watch the Traffic split bar fill with the new model's colour, and the row of stages at the top of this page move along: Shadow → Canary 5 → 25 → 50 → Full.

Any time · Rollout tab

Pull it back

Press Roll back. The stage row goes dim with a red line struck through it and every request returns to the old model instantly. The Audit tab then shows what the numbers were at the moment you decided.

Why do it this way?

Swapping a model all at once is how outages happen: the new one behaves differently on inputs nobody tested, and by the time anyone notices, every user has been affected. The alternative is to let the new model answer silently at first — it sees every request and its answers are recorded, but nobody receives them. Once its answers look right, it gets a small slice of real traffic, and the slice grows only while the numbers stay clean.

Everything on this page updates from the running service — nothing here is pre-recorded. The panel refreshes when you switch tabs or press Refresh rather than polling constantly, because a page that polls forever would keep the server awake and defeat the point of letting it sleep.

Promoting hands the new model a bigger share of live traffic: nothing → 5% → 25% → 50% → everything. Between steps the system watches two numbers — how often the new model errors, and how slow it is compared to the old one. If either crosses its limit the system rolls itself back automatically, without waiting for a human. Rolling back also clears the stored answers, so nothing produced by a model you have just stopped trusting can be served again.

What is measuredNowLimitStatus

Both models read every single sentence, even when only one of them answers you. That makes them directly comparable at no risk. The number that matters is the confidence gap: how far apart the two models were on the same sentence. A gap near zero means compressing the model changed almost nothing — which is exactly the result you want, and the honest finding here. A disagreement is the stronger signal: the two models reached opposite conclusions.

Most recent comparisons

Drift means the sentences arriving now no longer look like the ones the model was checked against. The system takes a snapshot of the first batch it sees and freezes it, then compares every later batch to that snapshot on two things: how long the sentences are and how confident the model is. A score of 0 means identical, 1 means nothing in common. This says nothing about whether answers are right — only whether the traffic still resembles what the model was measured on.

Latest check

If the same sentence arrives twice, the stored answer is returned instead of running the model again — far faster and far cheaper. This demo runs as a single server, and one server means one cache, so a plain dictionary in memory does the job that a separate cache service would normally do, with no network hop and no account. The panel names whichever store actually answered, because a stand-in that quietly takes the name of the real thing would hide a genuine outage.
