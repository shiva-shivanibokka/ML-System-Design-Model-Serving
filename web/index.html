What this is

This is a control panel for safely replacing one AI model with another while it is serving real people. The old model is v1. The new one is v2 — the same model compressed to run faster. The question this whole system exists to answer is: can we trust v2 enough to let it start answering real requests? You are the person deciding.

Swapping a model all at once is how outages happen: the new one behaves differently on inputs nobody tested, and by the time anyone notices, every user has been affected. The alternative is to let the new model answer silently at first — it sees every request and its answers are recorded, but nobody receives them. Once its answers look right, it gets a small slice of real traffic, and the slice grows only while the numbers stay clean.

Everything here updates from the running service — nothing is pre-recorded. The panel refreshes when you switch tabs or press Refresh rather than polling constantly, because a page that polls forever would keep the server awake for no reason. Start on the Manual tab if this is your first visit.

Everything you need to operate this panel, in order. Tabs run left to right in the order you would actually use them: send something, check the two models against each other, then decide how much real traffic the new one gets.

Step 1 · Predict tab

Send a sentence

Press Surprise me for a random sentence, or type your own, then press Classify. A large POSITIVE or NEGATIVE appears below the box — that is the answer, and the small print under it says which model produced it.

Step 2 · Comparison tab

See if they agree

Look at the first number, Average gap. That is how far apart the two models were — near 0 means they agree. Then look at the chart: one dot per sentence sent to the server so far, and a pink dot is one where the two models gave opposite answers.

Step 3 · Rollout tab

Give the new model traffic

Press Promote. Watch the Traffic split bar fill with the new model's colour, and the row of stages at the top of this page move along: Shadow → Canary 5 → 25 → 50 → Full.

Any time · Rollout tab

Pull it back

Press Roll back. The stage row goes dim with a red line struck through it and every request returns to the old model instantly. The Audit tab then shows what the numbers were at the moment you decided.

What each tab shows

Predict

Where you send text in. Both models score every sentence, but only one answer is returned to you — which one depends on the rollout stage. Sending the same sentence twice returns the stored answer without running the model at all.

Look at: the big verdict word, and answered by underneath it. There is no answer key — the verdict is the model's reading, not a checked fact. Sample sentences add what a person would call them, so you can spot a wrong answer.

Comparison

The two models scored side by side. The confidence gap is how far apart they were on the same sentence; a disagreement is the stronger signal, where they reached opposite conclusions. One dot on the chart is one sentence the server has handled — yours and everyone else's, since the count lives on the server and not in your browser.

Look at: Average gap first, then any pink dots on the chart.

Rollout

The controls. Promote hands the new model a bigger slice of live traffic — nothing, then 5%, 25%, 50%, everything. Between steps the system watches how often the new model errors and how slow it is compared to the old one, and rolls itself back without waiting for a human if either crosses its limit.

Look at: the Traffic split bar, and the Status column under Measured against limits.

Drift

Whether the sentences arriving now still resemble the ones the model was checked against. The first batch is frozen as a baseline and everything later is compared to it on two things: how long the sentences are, and how confident the model is. This says nothing about whether answers are right — only whether the traffic has changed shape.

Look at: the two scores against their limits. 0 is identical, 1 is nothing in common.

Cache

Repeated sentences return a stored answer instead of running the model again. The panel names whichever store actually answered, because a stand-in quietly taking the name of the real thing would hide a genuine outage.

Look at: Answered from cache — it climbs as you resend sentences.

Audit

Every change of stage with the numbers exactly as they stood at that moment. This is what makes a rollback explainable afterwards — not just that the system pulled back, but what it was seeing when it decided to.

Look at: Trigger — whether a person pressed the button or the system rolled itself back.

Nothing here knows the right answer. The model returns its own reading of the sentence and how confident it is — there is no answer key to check it against, which is true of every model serving live traffic. That is precisely why this system watches whether the two models agree and whether the incoming text has changed shape: both work without labels, and accuracy does not. The built-in sample sentences are the exception — those come with what a person would call them, so you can catch the model being wrong.

What is measuredNowLimitStatus

Drift means the sentences arriving now no longer look like the ones the model was checked against. The system takes a snapshot of the first batch it sees and freezes it, then compares every later batch to that snapshot on two things: how long the sentences are and how confident the model is.
